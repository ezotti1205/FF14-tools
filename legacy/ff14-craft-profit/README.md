# FF14 製作損益計算

FF14のクラフターで「素材から作る」と「完成品を買う」のどちらが得かを比較するツール。
ビルド不要の素のHTML/CSS/JS（ES modulesではなく classic script）で動きます。

```
index.html
css/style.css
js/store.js       localStorage 永続化（設定・状態・価格キャッシュ・エクスポート/インポート）
js/gamedata.js    アイテム名・レシピの静的データ（IndexedDBにキャッシュ）
js/universalis.js Universalis API v2 クライアント
js/calc.js        レシピ展開・必要数集計・原価計算・損得判定
js/ui.js          描画
js/main.js        起動と操作の配線
serve.ps1         動作確認用の簡易HTTPサーバ（Windows標準のPowerShellのみ）
```

## 起動

```bash
powershell -ExecutionPolicy Bypass -File serve.ps1
```

起動後 `http://localhost:8123/` を開きます。`index.html` を直接ダブルクリック（`file://`）でも
動く作りにしてありますが（外部データ取得先はいずれも `Access-Control-Allow-Origin: *`）、
そちらは未検証です。ブラウザによっては `file://` で IndexedDB が使えず、
レシピDBを毎回ダウンロードすることになります。

## データソース

| 用途 | 取得先 |
| --- | --- |
| アイテム名（日本語/英語）・レシピ | [ffxiv-teamcraft](https://github.com/ffxiv-teamcraft/ffxiv-teamcraft) の公開JSON（jsDelivr経由） |
| マーケット価格 | [Universalis API v2](https://docs.universalis.app/) |

レシピDBは `items.json` と `recipes.json` を初回のみ取得します（圧縮転送で合計約1.8MB）。
以後は IndexedDB に保存して再利用し、7日で自動的に再取得します（設定から手動更新も可能）。
localStorage は容量が足りないため、この辞書だけ IndexedDB を使っています。

XIVAPI v1（`xivapi.com`）は現在 HTTP 500 を返す状態だったため採用していません。
XIVAPI v2（`beta.xivapi.com`）は稼働していますが、レシピを1段掘るたびにリクエストが必要で
深いツリーでは数十リクエストになるため、一括取得できる静的JSONを選びました。

## 計算方法

- **必要数**: アイテム単位で合算してから製作回数を切り上げます。枝ごとに切り上げると
  同じ中間素材を余分に作る計算になり、原価を過大評価するためです。
- **素材の購入価格**: NQ の出品を安い順に必要数ぶん積み上げた実額。
  出品数が足りない場合は不足分を最後（最も高い）の単価で埋め、行に「出品不足」を表示します。
  出品が皆無なら直近取引の中央値にフォールバックし「出品なし」を表示します。
- **HQ/NQ**: 完成品はHQ/NQ両方の最安値と中央値を併記。判定は設定の「判定に使う完成品の品質」
  （既定はHQ優先、HQ出品が無ければNQへフォールバック）。素材の購入価格は常にNQです。
- **判定**: 「素材から作る総原価」と「完成品を同数マーケットで買った場合の総額」の比較。
- **手取り・利益**: 売値 × 製作個数 × (1 − 手数料率)。既定の手数料率は5%（設定で変更可）。
  利益率は 利益 ÷ 素材原価 です。
- **クリスタル類**（アイテムID 2〜19）は既定で「所持済み」＝原価0。行の「買う」に切り替えれば
  市場価格で算入されます。既定の挙動は設定でオフにできます。

## 素材の扱い（行ごとに切替）

| ボタン | 意味 |
| --- | --- |
| 買う | マーケット価格を原価に算入 |
| 作る | さらにレシピを展開して子素材から計算（レシピがある素材のみ） |
| 所持 | 所持済み／採集済みとして原価0 |

切替は**アイテムID単位**です。同じ素材が複数の枝に出てきても扱いが食い違わないようにするためで、
2回目以降に出てきた行は「↑集計済み」の参照行になり、数量は初出の行に合算されます
（合算された行には「合算」バッジが付きます）。

## 取得失敗時

Universalis の取得に失敗した素材は行が赤くなり「価格なし→手入力」と表示されます。
その行の**単価欄に直接数値を入力**すれば、そのアイテムだけ手入力価格で計算が続行されます。
完成品の行も同様に上書きできます。全件失敗してもアプリは動作し、すべて手入力で判定まで出せます。
空欄に戻せば市場価格に戻ります。

## キャッシュ

- 価格: localStorage に **15分**キャッシュ。ヘッダの「再取得」でキャッシュを無視して取り直します。
- 複数アイテムIDは**カンマ区切りで1リクエストにまとめて**送ります（最大100件/リクエスト、超過分は直列）。
- 各行の「更新」列と右カラムの「最終更新」に、Universalis 側の最終アップロード時刻を表示します。
  Universalis はユーザー投稿ベースなので、ここが古い場合は実際の相場と乖離します。

## エクスポート / インポート

設定画面からJSONで書き出し・読み込みができます（設定 + 選択中アイテム・数量・素材の扱い・手入力価格）。
価格キャッシュは含みません。

## 既知の制限

- ブラウザの `fetch` は仕様上 `User-Agent` ヘッダを上書きできません。代わりに識別用の
  クエリパラメータ `appName` / `contact` を付与しています（Universalis 側は未知のパラメータを無視します）。
- レシピDBは ffxiv-teamcraft のリポジトリ更新に追随します。新パッチ直後は反映が遅れる場合があります。
- 製作時の理論成功率・HQ率は考慮しません。完成品をHQで売る前提の計算をする場合は、
  HQを安定して作れることが前提になります。
